# 2026-09-17 P2A 目标检测与确认 MVP

## 结论

P2A 已实现并达到计划中的最短退出条件，现等待用户验收。新增检测器不会参与探索决策；
机器人只有在目标同时满足距离、水平视场、静态墙体视线和连续帧规则时才确认 `FOUND`。

在 `my_world.world`、3 台机器人、目标 `(-4, 4)`、3.0 m 最大距离、90 度水平视场和连续
3 帧确认的固定口径下，seeds 101/202/303 分别在 60.7/72.9/61.5 仿真秒确认目标。
三轮均由 `tb1` 发现，碰撞为 0、搜索重叠为 0。目标置于 `(100, 100)` 的 10 秒负例没有
触发，保持 `EXPLORE` 并按 timeout 结束。

## 实现边界

- `search_target` 是无 collision 的红色静态圆柱，仅用于可视化，不改变 lidar、真值地图或
  可通行空间。
- `target_detector` 从 `/gazebo/model_states` 读取目标和机器人真值位姿，用 P1B 的 world
  真值栅格逐段检查视线。
- 默认规则是 3.0 m、90 度水平视场和同一机器人连续 3 个可见帧；任一不可见帧清零该
  机器人的确认计数。
- 状态为 `EXPLORE → FOUND_UNCONFIRMED → FOUND`，通过 transient/reliable 的
  `/task_state` 和 `/target_detection` 发布。
- 评估器 schema 升为 v3，可记录发现机器人、目标位置、发现时间和检测参数；验证时可在
  `target_found` 后结束 episode。
- 功能默认关闭，P1C 行为不变。P2A 不停止或改写探索控制器，不分配集合点，也不实现
  目标消息可靠传播；这些分别属于 P2B 和 P3。

## 保留的基础设施失败

第一次补全 schema 后重跑 seed 101 的 episode
`p2a_target_detection_final_3r_seed101` 时，Nav2 lifecycle change-state 调用超时，内部门控没有
启动检测器和评估器，smoke 最终报告缺少 `/task_state`。该轮没有任务结果，不计入上表；原始
日志为 `log/smoke/robots3_seed101_20260917-120250.log`。把启动等待从 240 秒提高到 300 秒后
重试通过，未放宽 lifecycle active 条件或检测规则。

## 已知限制与下一步边界

当前检测器是可重复的仿真真值 MVP，不是 RGB/深度图像识别器；实物阶段仍需 AprilTag、
ArUco 或 RGB-D 检测及其误差模型。遮挡判断覆盖静态 world 中可栅格化的 box collision，
不处理动态机器人遮挡或 mesh 遮挡。P2A 验收后下一检查点才是 P2B：收到确认后停止探索，
为所有机器人生成不同且安全的 staging poses，并连续稳定 5 秒后进入 `COMPLETE`。
