# P2A 为什么长期无法完成：执行证据复盘

日期：2026-10-24。范围：当前项目工作树，执行结果截至 V74 实际闭合。

**核心判断：P2A 长期停滞，主要因为训练所依赖的执行、安全、测试和审计系统没有同时达到稳定、可验证、可负担的状态。工作持续回到训练前准备，尚未积累出一条合格的“采样—更新—保存最终模型—独立验证”完整链。当前证据不足以把失败归因于 PPO 学不会，也不足以认定研究目标不可实现。**

最近的直接卡点已经较明确：资格测试需要三台机器人分别完成两次合格的“运动中取消”，但固定测试中的候选目标、五秒承诺期、真实导航行为和 Reach 安全准入未能同时满足。解决这一项后，完整资格、运行容量和真实学习效果仍然需要验证，不能据此预计 P2A 马上完成。

本文只做项目复盘，不启动仿真、训练或新的科学重放，不修改现有门限、执行代码和历史结论。下文将“已记录事实”和“基于事实的工程判断”分开；报告版本号也不等于训练次数。

## 1. P2A 到底需要完成什么

现行出口是：神经网络实际选择三台机器人的探索目标，在 Gazebo 中完成被冻结的 95% 建图任务，无手工探索兜底、无真值输入，并形成至少一条完整可复现的训练和验证链。当前计划要求先满足同一执行冻结下的完整资格和容量，再完成有效 minimum 更新、剩余 pilot，以及最终模型的 open401/402/403 三场 strict95 开发验证。这三个编号属于开发验证，不是三个未见布局，也不是统计泛化证明。[现行实施计划](../IMPLEMENTATION_PLAN.md)

| 层次 | 项目已经取得的结果 | 仍缺的结果 |
| --- | --- | --- |
| 环境与接口 | P0、P1A、P1B、P1C、P2A.0 已验收；有观测、动作掩码、目标所有权、步进、重置、奖励和训练接口 | 当前改动后的执行配置不能直接继承所有旧资格 |
| 学习执行 | 历史版本真实做过采样、反传和参数更新 | 当前配置下的合格学习链与最终策略 |
| 安全与资格 | 多个局部脚本、CPU 检查和独立审计曾通过 | 新配置完整 12 回合、30 必需审计角色的合取通过 |
| 容量 | 有短任务和局部性能数据 | 含启动、重置、关闭、审计的实际训练与长验证容量 |
| 最终交付 | 有大量失败原件和问题定位证据 | 合格 pilot 的 final 模型及三场严格验证闭环 |

因此，CPU 测试 PASS、日志描述 PASS、归档 PASS，以及部分资格角色 PASS，都不能累计成 P2A 的完成百分比。P2A.0 的验收也没有承诺后续任意策略动作和任意新配置都稳定。[P2A.0 复盘](20261018_mr3_p2a0_reflection.md)、[V74 末账](assets/20261024_mr3_p2a_v74_reach_rejection_description/closure_ledger_v1.json)

## 3. 当前最直接的阻塞：测试需要的行为没有真正发生

“运动中取消”不是发送一个 WAIT 就算成功。当前测试需要同一目标已被接受且仍处于有效所有权下，满足五秒承诺、原动作掩码、正向速度至少 0.08 m/s、本目标新增路径至少 0.05 m，然后实际取消、观察终态与新鲜静止状态，并完成后续交接。每机两次，共六次，固定 32 步测试还约束接受和交接机会。当前代码在覆盖不足时明确抛出错误；32 次 step 返回只证明调用有结果，不证明上述行为出现。[测试生产器](../mr3_learning/benchmark.py)、[独立重放读者](../mr3_learning/reach_probe_masked_cancel_replay.py)

三次失败揭示了不同缺口：

| 尝试与后续描述 | 已确认的记录 | 对测试的影响 |
| --- | --- | --- |
| V67 → V68 | decision1 有合法 GOAL，但三机最大 masked 端点距离约 1.404、1.009、1.075 m，都达不到测试额外要求的 1.45 m screen | 有合法动作仍发不出测试所需 GOAL；整个回合记录 GOAL 为 0 |
| V69 → V70 | tb3 在 t2/t3 的接收速度约 0.199/0.095 m/s，路径已足，但 WAIT 掩码仍为 False；t5 首次收到 SUCCEEDED，已 idle | 出现运动的时刻不能合法取消；到允许窗口附近目标已经结束，不能取得要求的取消证据 |
| V71 → V72 | t5–10 接收状态满足 active/owned、WAIT 掩码等条件，但速度和新增路径条件不满足；三机 t10 新增路径仅约 0.00645/0.00650/0.00298 m | 时间和协议条件可用时，运动条件又没有成立 |

这些是离散接收记录，不能据此补造真实事件的生成、交付时刻或连续运动边界。它们支持的工程判断是：**当前测试设计尚未证明其全部要求能在给定候选、初始队形、导航和安全约束下同时实现。** 不能把每次覆盖失败都理解为“再修一个 reader 就能过”。[V67](20261024_mr3_p2a_v67_owned_stream_qualification.md)、[V68](20261024_mr3_p2a_v68_probe_stimulus_description.md)、[V69](20261024_mr3_p2a_v69_probe_v3_qualification.md)、[V70](20261024_mr3_p2a_v70_probe_v3_stimulus_description.md)、[V71](20261024_mr3_p2a_v71_masked_stimulus_qualification.md)、[V72](20261024_mr3_p2a_v72_masked_stimulus_description.md)

V73–V74 将 V71 的一部分阻塞进一步定位到了控制链：

- 在固定 `[44.72,49.72)` 窗口，每机 250 个控制 tick 中，tb1、tb2 收到的 raw 线速度请求本来就是 0；不能把三机都不平移归因于同一个安全拒绝。
- tb3 的 250 个 raw/effective 线速度请求均为正，237 个达到 0.08 m/s，但 Reach 输出线速度全部为 0。
- 拒绝涉及 tb3 相对于 tb2 的拟运动转换 X 证书；tb1 对应检查通过。223 条保留转向、制动平移，另外 27 条为转换包络拒绝。
- 首个保存样本中，记录的 map/raw 中心距约 0.6410/0.6334 m，而拟 X 所需 support-bound 距离约 0.7309 m。当前 D 检查约需 0.5713 m，可以通过。也就是说，“维持当前约束状态可以”和“准许进入平移过渡可以”是不同判据。

这是日志和源码对应支持的局部拒绝链。**条件充分安全证书拒绝，不等于真实碰撞、数学公式有错，也不等于所有合法方向都不可行。** body target 线速度为 0 也不等于双轮命令全零；APPLIED 标签不能代替电机写入、读回和机体响应证明。完整上游因果和新测试方案的可行性仍未闭合。[V73](20261024_mr3_p2a_v73_command_chain_description.md)、[V74](20261024_mr3_p2a_v74_reach_rejection_description.md)、[派生解释](assets/20261024_mr3_p2a_v74_reach_rejection_description/checks/derived_interpretation_v1/README.md)、[派生复核](assets/20261024_mr3_p2a_v74_reach_rejection_description/checks/derived_peer_review_v1/REVIEW.md)

截至本次阅读，V75 只是新的显式输入/阶段 workload 的 disabled 私有准备方向，尚无准入和执行成功证据。不能把“下一方案已提出”写成“当前问题已解决”。

## 4. 长期拖延的五个主要原因

### 4.1 安全假设与真实执行没有一次性对齐

项目确实遇到过真实问题：V7 的零线速度转向请求下，机体平面速度约 0.0202 m/s，超过当时纯转向模型的 0.01 m/s 条件；V13 的累计路径超过 7.8 mm；V52 长 KEEP 运行后来被定位为固定圆盘越界；V60 一次真实取消到 rest 为 3.031 s、0.2593 m，超过原 0.78 s、0.144 m 停止界。这些不是单凭“没有碰撞”就能忽略的检查。[V7](20261018_mr3_p2a_v7.md)、[V13](20261019_mr3_p2a_v13.md)、[V54](20261023_mr3_p2a_v54_firstfault.md)、[V60](20261023_mr3_p2a_v60_reader_registration.md)

**工程判断：** 高层目标接口虽然已经存在，底层执行模型对转向、制动、静止、交接和长时间保持的适用性仍反复变化。安全模型越依赖精确时序和物理边界，所需的端到端证据越多。局部模型修复必须保留，但不能把局部测试通过当成整个执行层稳定。

### 4.2 有合法动作，不保证有可执行且能完成测试的行为

动作掩码、Nav2 导航、Reach 检查和资格测试约束分别解决不同问题。高层 GOAL 合法，并不保证局部控制会产生能被 Reach 接受的正向速度；目标能到达，也不保证它能持续到承诺期结束后再被取消；能安全停止，也不保证已生成资格要求的有意义运动样本。

V67–V74 把这种不一致表现得很清楚。**工程判断：当前缺少对“这些约束的交集能产生所需行为”的提前验证。** 在交集尚无证据时，只调整候选长度、排序或时间安排，容易把一个阻塞换成另一个阻塞。这个判断不等于数学证明交集为空。

### 4.3 执行慢，审计和证据处理也很重

V50 reset native 约 4558 s，full 审计约 6342 s，完整 reset 阶段约 11303 s；这些时间有包含或重叠关系，不能相加。V60 中，open 的 32 仿真秒任务前缀约需 993–1016 墙秒，单 EP full 审计约 896 s。V52 保存约 15.63 GB 原始证据，归档工具实际等待约 1721 s；后者按项目规则记为 CPU 关闭工作、工程费 0，但现实时间成本仍存在。[V50](20261023_mr3_p2a_v50_qualification.md)、[V52](20261023_mr3_p2a_v52_qualification.md)、[V60](20261023_mr3_p2a_v60_reader_registration.md)

早期复盘已定位重复 TF 事件、完整 JSON 日志放大、历史列表反复扫描和大对象保留；V51 又实测到 JSON 解析和重复声明/ACK 全扫。V64 的局部等价优化确有软件证据，但局部 kernel 倍速没有转换成已通过的完整训练容量。[P2A.0 性能复盘](20261018_mr3_p2a0_reflection.md)、[V51](20261023_mr3_p2a_v51_runtime_profile.md)、[V64](20261024_mr3_p2a_v64_equivalent_hotspots.md)

**工程判断：** 项目瓶颈不仅在 Gazebo，更在整个“采集—日志—独立重放—关闭—归档”链。增加 GPU 或只优化一个数学函数，不能自动提高有效学习样本产出。容量必须端到端测量，当前 `capacity_qualified=false` 是实质阻塞。

### 4.4 验证工具和版本接线反复制造额外返工

有些失败没有提供新的机器人或学习知识。例如：V50 运行了新 probe，但部分 reader 仍只接受旧 workload；V59 新 profile tag 和事件未在公共读者中完整登记；V65 来源证明与当前输入不匹配；V66 计划引用的日志未进入冻结 Git 树。后两轮甚至没有启动 World。[V50](20261023_mr3_p2a_v50_qualification.md)、[V59](20261023_mr3_p2a_v59_encoder_profile.md)、[V65](20261024_mr3_p2a_v65_owned_stream_qualification.md)、[V66](20261024_mr3_p2a_v66_owned_stream_qualification.md)

保留原始失败、独立审计、来源绑定都必要；问题在于这些机制本身还不够稳定。已有复盘指出，活动验证工具依赖历史 report/assets 和多版动态加载链，会增加维护成本。当前每次很小的描述也有独立 consumer、parent、spec、测试、冻结和闭合；V72–V74 因而有充分来源记录，但它们仍只解释同一个 V71 失败样本。[P2A.0 流程复盘](20261018_mr3_p2a0_reflection.md)、[V72](20261024_mr3_p2a_v72_masked_stimulus_description.md)、[V73](20261024_mr3_p2a_v73_command_chain_description.md)、[V74](20261024_mr3_p2a_v74_reach_rejection_description.md)

**工程判断：** 证据管理和小活动的反复版本化，已经占用持续的实现、审阅和上下文维护精力。没有完整的人力/会话时间统计，不能声称它占总耗时的某个百分比，也不能把全部严谨性都视为浪费；可确认的是，部分返工完全可以与科学发现区分。

### 4.5 工程投入持续增长，学习产出与学习预算却没有同步增长

历史上确实发生过学习：V5 的 48 次更新和 V7 的 8 次更新都不能抹掉。但 V5 没有 final，V7 科学门失败；它们不能合并成当前配置的有效训练量。近几轮资格、诊断和归档则没有新模型更新。[早期训练](20261016_mr3_p2a.md)、[V7](20261018_mr3_p2a_v7.md)

当前 pilot 仍只有 1870 决策、约 48.43 分钟的剩余额度，且两种上限同时生效。工程额度增加不等于训练额度增加。现有数据没有建立当前可获得多少合格样本、这些样本是否足以产生学习趋势的关系，不能把“额度还在”当成“训练一定可完成”。也没有证据支持现在给出 PPO 必需样本数或保证某个时长可以学会。[V74 末账](assets/20261024_mr3_p2a_v74_reach_rejection_description/closure_ledger_v1.json)

**工程判断：** 持续投入主要换来了工程知识和局部修复，尚未转化成稳定的学习实验。项目需要同时回答“能不能安全采样”和“能否在可用成本内积累足够的有效采样”，只解决前一个问题仍可能继续停在 P2A。

## 6. 为什么大量 PASS 看起来没有带来完成

项目文档反复出现 PASS，但对应的证明对象不同：

| PASS 类型 | 它能说明什么 | 它不能说明什么 |
| --- | --- | --- |
| 人工 CPU 检查 | 程序在构造输入下满足检查 | 真实导航会进入这些状态 |
| 原生 step 返回 | 请求完成并返回记录 | 所需运动/取消覆盖已取得 |
| 字段描述通过 | 固定日志被完整解析，字段可交叉核对 | 原活动成功、修复有效或物理根因已明 |
| 来源/关闭/归档通过 | 被核范围内来源可追溯、进程退出、原件可恢复 | 科学结果或策略有效 |
| 部分角色通过 | 相应局部判据通过 | 全部资格完成、长时稳定 |
| 实际优化器更新 | 参数确实变化 | 数据合格、学到收益、95% 验证通过 |

例如 V74 的账本同时写有 `activity_passed=true`、`scientific_qualification_credit=false`、`capacity_qualified=false`、`P2A_complete=false`，并不矛盾：通过的是固定日志字段描述。V71 的原生失败仍被保留。后续派生解释定位了 tb2 拒绝，但原账本的 `root_cause` 仍为 `UNKNOWN_PENDING_SEPARATE_DERIVED_ROUTE_REVIEW`，不能改写成完整根因已解决。[V74 末账](assets/20261024_mr3_p2a_v74_reach_rejection_description/closure_ledger_v1.json)

文档维护也增加了理解成本：当前实施计划顶部已经记录 V74，但 P2A 主节仍保存 V69/V70 及当时“私有准备”的叙述，ROS 指南也包含更早的入口快照。带日期的历史记录有保留价值，但阅读者必须逐次区分“当前状态”和“当时下一步”。本文采用最新实际闭合结果，不把旧准备段当作今天待执行的授权或结果。[实施计划](../IMPLEMENTATION_PLAN.md)

## 7. 对项目推进方式的判断，以及应怎样收敛

**项目确有必要的底层修复，也有可避免的执行和流程返工。** 把全部问题归咎于“验收太严”会忽略真实物理反例；把全部失败归咎于“RL 太难”又会忽略多数近期活动根本没有进入学习。最需要改变的是取得证据的顺序和工程投入的评价方式。

以下是本次评估建议，不是已执行方案，也不改变现行资格和验收要求。

| 优先事项 | 需要回答的具体问题 | 应交付的结果 |
| --- | --- | --- |
| 先验证当前测试的可行性 | 在原 mask、安全、五秒承诺和停车界下，是否能用有限、预声明的输入安排产生六次要求的运动取消？ | 一条真实可追踪的目标→请求→Reach→应用→运动→取消→静止链；若失败，给出明确阻断条件，不无限追加试到成功 |
| 在昂贵运行前完成公共入口检查 | producer、所有公共 reader、profile、来源清单和 Git 内容是否一致？ | 用真实入口的小检查提前发现 V50/V59/V65/V66 类缺口，而不是完整运行后才发现 |
| 独立测完整成本 | 包含 cold start、reset、关闭和审计后，剩余额度实际能完成什么？ | 当前配置的容量结论；不得用短 probe 或局部加速倍数代替长任务成本 |
| 将局部修复转为最终资格证据 | 修复是否真的同时满足完整矩阵全部要求？ | 新的同冻结 12EP/30 角色结果；诊断通过不填补资格缺项 |
| 最后检验学习 | 合格数据是否产生实际更新、最终模型和规定验证结果？ | minimum、pilot、final 三层独立结果；没有结果时明确保持 P2A 未完成 |

对工作流还建议做两项有限整理：一是将成熟活动工具逐步从历史证据链中分离，使用明确的版本/profile 接口并保持独立判据；二是用一张简短当前状态表记录“阻塞、证据、下一次能证伪的假设、退出条件”，历史长记录留在日期报告。这样可以减少重复接线与接手误读；不需要为此先做一次大规模框架重写。

继续推进的价值应由“新增合格行为、减少哪项确定阻塞、提高多少端到端容量、是否产生有效学习”衡量。单纯增加报告版本、CPU 数量、来源数量和归档字节，不足以说明距离 P2A 更近。如果有限的新测试仍不能产生所需行为，应明确评审执行契约与工作负载的相容性；如果容量仍不成立，应评审采样路线与预算。不能持续用扩充工程额度替代这两个判断。

## 8. 目前可以下的结论与不能下的结论

可以确认：P2A 当前仍被训练前条件阻塞；近期直接缺口是运动取消覆盖，另有完整安全资格和容量缺口；此前真实执行故障、工具兼容问题和重型审计共同拉长了周期；既有学习记录没有形成当前可验收的最终模型及三场验证链。

不能确认：PPO 天生不适合该任务、95% 目标不可达、Reach 数学错误、tb2 会造成真实碰撞、V75 一定能通过，或者再投入固定若干小时就能完成。也没有依据现在用更换算法、更大网络或更多 GPU 作为主要解决方案。

**对“为什么这么久还没完成”的直接回答是：项目一直在修建并反复验证学习所需的执行基础，而这套基础的行为可行性、物理适用性和成本尚未同时闭合；验证体系自身又不断产生返工，所以大量工作变成了准备与诊断，尚未转化为一个可靠的学习交付。**
