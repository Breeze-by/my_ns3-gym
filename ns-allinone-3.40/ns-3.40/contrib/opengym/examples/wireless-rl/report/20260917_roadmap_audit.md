# 2026-09-17 P2B 前路线与指标审计

## 审计结论

总体研究方向正确：先得到可靠的理想通信任务闭环，再建立显式消息和网络因果关系，最后比较
通信策略与 RL。原计划的主要问题不是方向错误，而是部分阶段跨度过大、退出条件不够可判定，
并缺少从“组件完成”到“完整任务完成”的集成门。

本轮只修改研究和工程验收合同，没有启动 P2B、没有修改算法/模拟规则，也没有运行新的
Gazebo/ns-3 实验。P1C、P2A 的历史结果和验收结论保持不变；用户已于 2026-09-17 验收
P2A。

## 发现的问题和修复

### 1. 最终任务成功定义不够严格

原文同时使用 90% 覆盖、`FOUND`、集合完成等概念，后续实现容易把提前发现目标误写成任务
成功。现统一为：P2B 以后只有全体 required robots 在不同 staging poses 满足位置、速度和
连续保持条件后的 `COMPLETE` 才是 `success=true`。`FOUND`、覆盖率和地图准确率是过程
指标。最终任务不要求先达到 90% 覆盖；目标可能更早被发现。

第一版集合完成条件固定为：位置误差不超过 0.35 m、线速度不超过 0.05 m/s、角速度不超过
0.10 rad/s、全体连续保持 5 个仿真秒；任何机器人离开或重新运动都会重置保持计时。
required set 在 episode 开始时固定，不能静默删除失败机器人。

### 2. P2B 原退出条件无法直接指导实现

原条件只有“不同安全位置稳定 5 秒”，没有规定谁拥有状态、何时停止探索、怎样处理活动 goal、
安全位姿的约束和失败原因。现要求权威任务协调器在首次有效 `FOUND` 后：

1. 成为 `/task_state` 的唯一发布者；P2A 检测器只产生观测/确认事件；
2. 停止新探索分配并取消所有活动探索 goal；
3. 在已知自由空间生成可达、障碍净空至少 0.45 m、相互间隔至少 0.8 m 的不同集合位姿；
4. 进入 `RALLY`，跟踪 Nav2 重试和全体稳定保持；
5. 只在统一完成条件满足时进入 `COMPLETE`；
6. 对集合空间不足、导航重试耗尽和 timeout 给出明确失败原因。

P2B 仍是理想同机 ROS 交付，不声称目标消息已经经过网络。正式检查以 3 台机器人
seeds 101/202/303 为主，2 台只做一次交叉验证，符合当前节省验证时间的约束。

### 3. P2C 可以被“电池永远够用”空洞通过

原条件只说低电量返航，没有要求 episode 中真实发生充电。现要求至少一个预先固定参数的
episode 必须迫使一台或多台机器人返航充电，并在不耗尽的前提下保留地图/任务状态、充满后
恢复并继续任务。无法返航、耗尽、充电超时必须是可观察失败。

在 P3 尚无真实通信字节账本时 `c_tx=0`，避免虚构通信能耗。仿真第一版为每台机器人提供
非重叠充电位，避免把充电排队引入为额外研究变量；实物阶段再按实际充电设备能力冻结容量。

### 4. 缺少完整理想任务集成门

P2A、P2B、P2C 分别通过并不证明探索、检测、充电和集合能在同一 episode 中工作。新增
P2D：在接网络之前，用至少三个预先验证的 `(world, target pose, energy profile)` 场景，
每个运行 seeds 101/202/303，并用最难场景做一次 2 机器人交叉检查。目标位置必须变化，
且正式运行前确认周围存在足够集合空间，避免继续只对 `(-4, 4)` 过拟合。

P2D 初始硬上限为 300 仿真秒。若 pilot 证明不合理，只能在正式批次前统一修改并记录原因，
不能对不同 seed 或策略使用不同上限。P2D 是后续通信实验的 ideal task upper bound；不直接
套用 P1C 的 180 秒/90% 探索门槛。

### 5. 显式通信边界遗漏了关键旁路

源码核对显示：当前 `merge_map` 直订 `/tbN/map`，中央协调器直订 `/merge_map`、
`/tbN/map`、`/tbN/odom`、`/tbN/tf` 并直建 `/tbN/navigate_to_pose` action client；P2A
检测器集中读取 `/gazebo/model_states` 后发布全局目标事件；当前 1–3 号机器人的 Nav2 全局
代价图又直接订阅中央 `/merge_map`。若只给某些话题增加网络延迟，正式实验仍会旁路 ns-3。

P3A 现要求完整替换：机器人本地地图、位姿、电量、状态和检测进入候选消息队列；中央只读
gateway 已交付的信息存储；融合地图版本/相关区域及探索/返航/集合命令经下行 gateway 后由
机器人本地适配器交给 Nav2。P2A 的仿真真值逻辑可作为“机器人本地传感器模拟器”，但中央
不得订阅原始检测结果；机器人 Nav2 也不得免费订阅中央最新融合图。评估器仍可读真值，但
只能输出指标。

新增机器可检查的 forbidden-bypass 清单和自动检查。`ideal/unlimited` 也必须走同一 gateway，
仅把网络设为零丢包、零附加时延和无限准入，禁止保留旧直连形成两套任务实现。

### 6. P4 同时解决时间同步和无线建模，问题跨度过大

P4 拆为：

- P4A：只完成固定时间窗/lock-step、Gazebo mobility、真实消息大小和 ns-3 逐包账本；相同
  seed 重复结果一致，应用生成/准入字节与 ns-3 发送/交付字节闭合；
- P4B：再加入 802.11n AP+2/3 STA、传播、墙损耗和背景干扰，参数必须有实测或公开依据。

这能把时间竞态、消息桥错误和 Wi-Fi 参数问题分开。网络指标应形成可解释梯度，但不要求每个
seed 的任务时间人为单调。

### 7. 正式实验协议和失败处置不够明确

现规定每个启动尝试都保留：`episode_start` 前的 spawn/Nav2/进程问题记为
`infrastructure_failure`，修复后可用相同元组重跑，但原失败进入基础设施可靠性统计；
`episode_start` 后的 timeout、掉线、规划、电池、碰撞或进程故障都是任务失败，不能用补跑
成功样本替换。正式批次固定 commit、配置哈希、场景和 seed 清单，改代码必须开新批次。

Gazebo、场景、网络、策略使用独立显式 seed。各策略使用相同测试元组做配对比较。所有
baseline 包括 ideal 都共享消息和任务实现，只改变通信准入/网络条件。

### 8. RL 退出条件容易鼓励“调到获胜”

工程正确性和科学结果现被分开。P6 工程通过条件是可部署观测、硬安全覆盖、validation-only
选模和 held-out 评估链路正确，不要求必须胜过全部 baseline。P7 至少使用 20 个独立且策略间
配对的 held-out episode：先报告 success rate 及 95% Wilson 区间，再报告固定 horizon 的
RMST 和通信指标配对 bootstrap 区间。只有相对最强非学习 baseline 的预注册主指标区间支持
改善且安全不退化时，才声称 RL 有优势；否则如实保留负结果。

若合理地图消息、检测证据和实测背景流下 Wi-Fi 不是瓶颈，先报告这一事实，不允许为制造 RL
优势而加入无法解释的拥塞。

### 9. 仿真真值检测没有通向真实相机的明确门

P2A 作为可重复真值 MVP 是合理简化，但不是最终视觉成果。P8 现拆为 P8A/P8B：P8A 必须恢复
真实相机检测适配器、UDP gateway、时钟同步和单机器人安全流程；P8B 才进行双机器人完整
任务及 sim-to-real 对比。实物结果不得复用 Gazebo 真值位置。

### 10. 原 DQN 动作只列两机器人上行，和 3 机器人/地图下行不一致

原动作示例只包含两台机器人的状态、地图和检测上行，却没有当前 Nav2 依赖的融合地图下行，
也没有说明 3 机器人如何扩展。现把动作语义改为“准入某 endpoint 的某类候选消息”，同时
覆盖上行状态/地图/检测和下行融合地图/任务命令。实际最小集合在 P5 根据真实候选队列和瓶颈
测量冻结，不为未出现的消息预留动作。2/3 机器人共享动作生成规则，但分别训练固定维度
checkpoint；不为跨数量泛化提前引入复杂可变规模网络。关键消息仍有最大等待时间，RL 不能
永久压制检测、返航或急停。

## 修订后的关键依赖

```text
P2A accepted
  -> P2B rally correctness
  -> P2C energy/charge correctness
  -> P2D full ideal mission baseline
  -> P3A one gateway path, no bypass
  -> P3B deterministic delay/loss causality
  -> P4A ns-3 packet/time correctness
  -> P4B calibrated Wi-Fi behavior
  -> P5 frozen protocol + non-learning baselines
  -> P6 DQN engineering evaluation
  -> P7 generalization/statistics
  -> P8A single-robot real perception/network
  -> P8B two-robot hardware task
```

## 保留不变的边界

- 不重新实现 SLAM、Nav2、Wi-Fi MAC 或视觉基础模型；
- 不提前引入 PPO/MAPPO、D2D、未知初始位姿配准或复杂地图压缩；
- 安全避障、低电量返航和急停永远不交给 RL；
- 2 台机器人是最终最低可交付，3 台是主要仿真验证规模；
- 历史 P1/P2A 报告保持原样，不用新计划改写历史实验事实。

修订后的正式状态、阈值和退出条件以 `IMPLEMENTATION_PLAN.md` 为准；长期研究定义和统计
规则已同步到 `RESEARCH_PLAN.md`。
