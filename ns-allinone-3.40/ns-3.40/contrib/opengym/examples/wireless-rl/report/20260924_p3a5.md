# P3A/P3A.5 当前 HEAD 修复报告（2026-09-24）

## 范围

本报告记录 `78b64be` 之后对 ROS 2 task stack 的 P3A/P3A.5 修复和验证。最终冻结候选为 `2933c24`。P3A 的目标是让中央地图、位姿、电量、检测和 Nav2 命令都经过显式 zero-loss gateway；P3A.5 要求在当前提交上重跑固定 P2D/P3A 矩阵并冻结结果。

## 诊断

此前正式矩阵的失败来自两类状态问题：

1. 机器人真实起点可能是已知自由格，但被 clearance mask 的膨胀区域排除，中央规划因此错误地认为无路。
2. Rally 的串行 parked pose 会堵住后续机器人的唯一路线；action 拒绝、取消和 probe 超时还可能留下 stale 状态。电池管理器同时直接向机器人 Nav2 action 发返航目标，与协调器的取消竞态会把机器人留在 lethal 起点附近。

## 修复

- 新增 `navigation_start_cell`：只允许 raw map 已知自由的起点在有限半径内逃逸到 clearance 可行格，未知或占用起点仍拒绝。
- 在 rally recovery 中同时保留临时让路位和最终位；只移动真正阻断目标路线的 parked robot。
- 在 RALLY 入口枚举小规模串行顺序，用动态占位检查每个后续路线；完成判定等待所有 goal、probe、yield action 清空并满足稳定时间。
- 对 survey/rally action 的异常、拒绝、取消和 stale handle 显式清理；成功的中间 leg 重置尝试计数。
- 电池返航使用 gateway action `/gateway/<robot>/navigate_to_pose`，并将该直连模式加入旁路源码审计。
