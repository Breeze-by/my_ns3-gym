# 2026-09-17 P2B 集合状态机

## 结论

P2B 已实现并达到修订计划中的退出条件，现等待用户验收。协调器是
`/task_state` 的唯一权威发布者；目标确认后会取消全部探索、为所有 required robots 分配
不同的安全集合位姿，并且只有全体位置和速度连续 5 个仿真秒满足门槛才进入 `COMPLETE`。

最终代码在 `my_world.world` 上完成 3 机器人 seeds 101/202/303 和一次 2 机器人 seed 303
交叉验证。四轮全部以 `task_complete` 结束、碰撞为 0；3 机器人完成时间为
134.5/171.9/177.3 秒，最大最终位置误差 0.237 m，最小集合位姿间距 1.210 m。

## 实现边界

- `target_detector` 只发布 `/target_observation` 和一次性的 `/target_detection`，不再发布
  全局任务状态。
- `headquarters_control` 校验状态转移并发布 transient/reliable 的 `/task_state`、
  `/rally_assignments` 和 `/task_failure`；终态 `COMPLETE`/`FAILED` 不可重新打开。
- 首次确认后取消所有探索 goal。若目标周围地图尚不完整，发现机器人最多执行有界的已知
  自由空间 survey；仍无足够位姿时明确失败为 `insufficient_rally_poses`。
- 集合候选来自已知自由地图，朝向目标，最终点障碍净空至少 0.45 m；分配硬性要求相互间距
  至少 0.8 m，并优先达到 1.2 m。
- 集合路径按 0.35 m 障碍净空规划，每个 Nav2 goal 最长约 1.5 m。目标背侧/深处位姿先
  入场，防止已停机器人阻塞后来者；每台机器人仍保留有界重试和显式失败。
- `COMPLETE` 要求每台平面误差不超过 0.35 m、线速度不超过 0.05 m/s、角速度不超过
  0.10 rad/s，且全体连续稳定 5 秒；任一条件破坏会重置保持计时。
- 评估器 schema v4 记录 `time_to_rally`、`completion_time`、分配位姿、最小间距、逐机器人
  最终误差/速度和任务失败原因。smoke 的 `--rally` 还要求零碰撞。

这里仍是同机 ROS 理想直达事件，没有伪装成网络验证。检测器仍使用 Gazebo 真值，协调器仍
直读中央状态并直接调用 Nav2；这些旁路必须在 P3 由统一 gateway 替换。

## 正式验证口径

共同环境：ROS 2 Humble、仓库内 symlink install、`TURTLEBOT3_MODEL=waffle`，每轮使用独立
`ROS_DOMAIN_ID`。P2B 是完整“探索→发现→集合”任务，统一上限为 300 仿真秒；P1C 的
180 秒是覆盖率任务上限，不适合把较晚发现目标和顺序安全入场截断。位置、速度、保持、间距
和零碰撞标准没有因延长上限而放宽。

3 机器人命令模板：

```bash
PYTHONNOUSERSITE=1 python scripts/ros_smoke_test.py \
  --world my_world.world --robot-count 3 --gazebo-seed <101|202|303> \
  --startup-timeout 360 --message-timeout 90 --shutdown-timeout 60 \
  --evaluation-duration 300 --coverage-threshold 0 \
  --evaluation-wait-timeout 480 --target-detection --rally \
  --target-x -4 --target-y 4 --target-max-distance 3 \
  --target-field-of-view 90 --target-confirmation-frames 3 \
  --episode-id <episode-id>
```

## 失败演进与算法修正

所有 post-start 失败都保留，没有用重跑覆盖：

- 初版只检查少量候选，造成 `insufficient_rally_poses`；移除候选截断并加入目标区 survey。
- 直接发送远端集合 goal 时，机器人会在长走廊/转角失败；改为基于已知地图的 1.5 m
  分段路径和顺序进场。
- survey action 与状态切换曾存在竞态，导致 survey 未完成即进入 `RALLY`；现在等待 pending
  和 active handle 全部结束后再分配。
- seed 303 的早期 300 秒轮虽进入 `COMPLETE`，但有 6 次接触，因此判 FAIL；0.35 m 集合
  路径净空消除了该轮碰撞。
- 随后 seed 101 暴露 tb2/tb3 先后经过同一入口并产生 5/4 次对称接触。把路径净空硬升至
  0.45 m 会封闭实际可通过的窄通道并明确失败；最终采用 0.35 m 路径净空，但按团队接近
  方向先填目标背侧位姿，既保持可达性又消除已停机器人阻塞。
- 多 Nav2 冷启动仍偶发在 episode start 前缺 lifecycle/topic。它们作为基础设施失败保留并
  用完全相同参数重试，不计作算法 episode；正式四轮都通过完整 readiness gate。

全部尝试、原始 log/JSON 文件名和阶段性结论见 `log.md`；原始运行产物位于忽略目录
`ros2_ws/ros2-multi-robot-automap/log/`。
