## 阻塞原因与继续投入的价值

**真实执行问题需要修复，但不足以否定 RL 方法。** 转向漂移、停车响应、SLAM 关闭异常、DDS 历史缺失等曾真实发生。V13 在独立 38 角色工程资格通过后，fresh16 minimum 仍出现原累计漂移模型失败，说明脚本工程资格不能替代真实策略动作验证。新 [reach 契约](../MR3_REACH_CONTRACT.md)增加了模式交接、固定锚、实际应用回执及双坐标证书，当前仍缺完整原生资格。样本级必要条件通过也不是连续动力学安全定理。

**审计与编排自身已成为研究成本。** V19 接口原生约 1063 秒返回成功，整个 interface 阶段约 3790 秒，超出约 2391 秒有效 cap；Information 读者最终被受控中断。V20 对历史扫描和重复编码的优化有价值，两个完整重放分别约 340、423 秒通过，但没有证明新完整矩阵、实际训练和长回合的端到端容量。不能据不同并发条件的墙时宣称纯代码加速倍数。更早的日志放大、二次复杂度扫描及活动工具依赖历史档案链问题，见 [P2A.0 复盘](20261018_mr3_p2a0_reflection.md)。

**学习预算和问题规模不匹配。** 现有剩余 pilot 是 1870 次决策与约 48 分钟墙时的双重上限，新计划从头训练；这适合检验采集与更新能否闭合，不足以用失败判断 PPO 学不会任务。训练器 [ppo.py](../mr3_learning/ppo.py)先等待采集回合关闭，再构造 rollout 和更新；墙时、关闭失败和短回合重启都影响实际可训练样本数。[reach_policy_chain.py](../mr3_learning/reach_policy_chain.py)及 V19 计划将 pilot 配为两 worker、每回合上限 64 决策、原生上限 2100 秒，1870 不是保证能取得的样本数。

[SB3 官方说明](https://stable-baselines3.readthedocs.io/en/master/guide/rl_tips.html)指出模型无关 RL 往往需要大量交互，有时达到百万量级。这不构成本项目的必要样本下界；本项目所需样本与可负担吞吐仍须实测。历史 [二维选项容量分析](20261015_mr3_2d_option.md)中，W7 四 worker 的短回合实测速率约 0.201 有效 transition/墙秒，距候选 500k/72h 门槛约 9.6 倍；该结果属于旧冻结和短回合，不能直接预测当前 reach 配置或完整移动训练成本。

已有接口和原件值得复用；继续投入应换取稳定采样、容量和学习趋势的新证据，而不是继续增加工程 PASS。

## 建议调整的推进顺序

以下是评估建议。现行 [研究计划](../RESEARCH_PLAN.md)、[实施计划](../IMPLEMENTATION_PLAN.md)及已接受科学契约仍有效；不能引用本节绕过完整资格或直接启动新训练。

1. **先收口原生可行性。** 先用已有原件和源码整理一份有限诊断计划，明确要回答三个问题：当前配置能否连续完成多回合移动、停止和重置；实际策略动作是否频繁触发永久停止；含启动、关闭、审计和失败的有效训练吞吐是多少。计划应给出确切场景、seed、动作来源、回合数、决策数、全部消费者、总墙时、费用归属及停止规则。小诊断不冒充完整资格，不缩减当前矩阵后标 PASS；新增范围或规则变化须按实际授权处理。
2. **按影响区分执行与审计版本。** 提议分别绑定运行时源码、ELF、配置、权重与离线审计器。运行时和封存输入不变时，等价的审计器性能修复优先在原件上复核；修改影响执行或科学语义时，再对受影响范围重新采样。必须保留独立 oracle、全部谓词、来源校验和旧失败；不能让 producer 自证替代独立核查。该方案是前瞻契约调整，不能借它补造 V19 矩阵通过或直接解锁 PPO，也不需要先做大规模框架重写。
3. **倾向快速二维预训练，原生迁移与正式验收。** 以现有二维候选为起点，先明确近似与符合性，再做有限容量验证，之后才决定训练。固定三机器人、received-only 边界及候选和动作含义；尽量复用纯 Python 规则。二维不提供真实 SLAM/Nav2、DDS、刚体接触和原生关闭信用。零样本迁移、必要微调及正式 95% 验收仍回到 ROS/Gazebo。二维、微调、随机初始化对照与评价分别计账，不能假定迁移成功或直接使用未批准的 500k/72h 候选额度。
4. **暂留 PPO 与稳定子目标。** 当前没有证据支持靠换 DQN/SAC、更大网络或直接速度控制解决这些阻塞。先证明稳定且可负担的采样，再依据学习曲线和失败类型诊断候选、表示、奖励或算法。工程链闭合与学习效果分开报告；P2A 的原 95% 和完整训练验证出口不因拆分报告而降低。

## 停止条件与后续决策

- 下一份诊断计划应预先固定一次诊断活动的总上限和退出条件；失败后给出结论与下一选择，不自动追加回合、扩额或完整矩阵。若当前执行配置仍不能稳定产生有效样本，停止扩大原生 PPO 训练投入，保留未完成状态。
- 如果快速环境在预声明训练预算内没有学习趋势，先诊断表示、候选、奖励及任务可达性，不直接把更多 Gazebo 时数当补救。学习趋势需和未训练策略及适当同接口基线比较，单次达到 95% 不足以证明收益。
- 如果快速环境表现可用但迁移持续出现规划失败、接触或执行故障，停止扩大预训练，回到模型差异及原生执行接口诊断。
- 三机器人、95%/300 秒、地图质量、真实参与、18 路接触监测、信息边界和导航闭合继续有效。不增加真值输入、手工探索兜底，不拼冻结、不筛掉失败、不把二维成绩转为原生 PASS。
- 如果用户决定论文重点改为 Wi-Fi 对协同建图的影响，可以另议固定传统策略的网络研究路线；这是研究问题调整，不是 P2A 验收或 gateway 授权。未经这种明确决定，P2B 及 gateway 仍未开始。
