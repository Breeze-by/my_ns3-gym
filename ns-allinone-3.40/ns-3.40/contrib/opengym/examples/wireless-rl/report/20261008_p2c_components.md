## 实现与边界

返航不再用欧氏距离乘系数代替完整已知路径，也不以第一个短航段的长度估计完整返航。中央使用其实际交付地图；本地优先新鲜且有完整路线的自有地图，再尝试实际交付的融合地图。源头地图仍须满足原 5 s TTL，中央位姿/TF 仍为 2 s。未知、占用或断连不能得到有限路径预算。接触区距离场与返航短腿共享完整接触端点，保留既有 0.35 m 路径净空、0.6 m 已知自由起点逃离规则、可见短段与对角不穿角检查。

候选成本为 `移动成本×(完整路径×既有factor + 反应距离) + 空耗×(名义行程时间 + 有界恢复等待 + 地图/位姿源龄 + 反应时间) + 既有安全余量`。默认恢复等待 30 s；安全 tick 0.5 s，显式留 1 s、0.3 m 的反应余量。中央探索、集合、返充请求及 refuge 去程终点均检查完整返回预算。已在 RETURNING 的机器人的未来充电后任务分配可用原返航超时计入名义等待；这不把当前未知路线伪造成可执行返航。

本地失路先取消并保留原 action handle 等待结果，暂停新增导航；默认 30 s 内未恢复则在正能量条件下显式失败。原总返航/充电时限未延长。原始预测路径包络、时间包络和安全余量下限提供运行期停止条件，越界失败必须保留；不能用重新计算预算来抹掉原预测。临时地图缺口恢复且预算仍充分时继续保留任务，无须强制充电。CHARGING 过渡在取消未完成或超过原充电静止阈值时继续计耗；原充电接触/静止/保持定义不放宽。

`/{robot}/battery_return_audit` 是只读本地安全证据，保留源地图压缩内容、来源/版本/源时刻/哈希、完整预测路线和能量组成、实际距离/时间/成本、取消/拒绝与误差。AP 不订阅该审计快照。新增电池状态字段正常计入 gateway 的真实控制字节；旧 P3C.5 的流量比例不能直接沿用。没有新物理能量标定，单位是模型单位而非 J。

预算是**条件包络**：假定实际路程偏离、反应、执行器速度和恢复等待有界。最短路径与名义速度不是无条件最坏情况证明；无限堵塞、动态障碍、执行器失效和未标定硬件超出该声明。零耗尽样本也不证明普遍安全。地图旋转/里程跳变等继承模型限制仍需单独研究。

## 四种方法的组件比较

固定 seed 20261008，四种布局（开阔、绕墙、迷宫、断连）、64/128 两种栅格、每格 24 个查询，共 192 个查询。旧直线系数仅作历史诊断；前向 Dijkstra 和具有可采纳欧氏启发式的 A* 作完整已知图参考；候选部署多接触点反向 Dijkstra 内容缓存。完整三种方法的成本/不可达判定一致；旧直线系数有 46 次低估和 28 次不可达却给有限值。

在本机 Python 3.10.12/SciPy 1.8.0 的此组件实现中，查询耗时中位数：前向 Dijkstra 7.89 ms、Python A* 24.30 ms、已有缓存查询 0.258 ms；P95 分别 21.07/195.35/0.322 ms。冷构建成本逐场景保留在 [v3 原记录](20261008_p2c_algorithm_components_v3.json)。缓存按实际地图内容、dtype、分辨率、原点、充电位和接触半径失效，不缓存源龄或准入结论。v2 原比较及 v1 JSON 序列化失败仍保留，不能用组件 CPU 差宣称任务因果提速或普遍优于其他 A* 实现。实现接口依据 [SciPy Dijkstra 官方文档](https://docs.scipy.org/doc/scipy/reference/generated/scipy.sparse.csgraph.dijkstra.html)。
