# P1C 多机器人协同探索加速与导航闭环

日期：2026-09-17

## 结论

P1C 已在不修改 world、真值栅格、90% 覆盖定义、传感器、机器人速度或碰撞统计的前提下，
完成 2/3 机器人同口径三 seed 验证。相对 2026-09-16 的两机器人基线，`time_to_90`
均值从 145.9 秒降到 94.3 秒，缩短 35.4%；三机器人均值进一步降到 72.5 秒。

建议保留 180 仿真秒作为暴露故障的硬上限，并将当前 P1C 速度验收线设为：固定 seeds
101/202/303 中，两机器人最慢不高于 120 秒，三机器人最慢不高于 90 秒。600 秒会掩盖
规划或协同故障，不再使用。

## 固定实验契约

- world：`my_world.world`
- 出生/充电区：半径 1 m 的共同起始区；tb1 `(0,-0.45)`、tb2 `(0,0.45)`、
  tb3 `(0.45,0)`
- seeds：101、202、303
- 成功：`correct_free_coverage_ratio >= 0.90`
- episode 硬上限：180 仿真秒；达到阈值立即结束
- 目标速度上限、lidar、真值和 evaluator 均未修改

正式命令仅在 `robot-count`、seed 和 episode id 上变化：

```bash
source /opt/ros/humble/setup.bash
cd /home/zhuyulab/ns3-workspace/ros2_ws/ros2-multi-robot-automap
source install/setup.bash
python3 scripts/ros_smoke_test.py \
  --robot-count ROBOTS --gazebo-seed SEED \
  --evaluation-duration 180 --coverage-threshold 0.90 \
  --evaluation-wait-timeout WAIT --startup-timeout STARTUP \
  --message-timeout 90 --shutdown-timeout 60 \
  --episode-id EPISODE
```

两机器人使用 `WAIT=270, STARTUP=180`；三机器人使用
`WAIT=300, STARTUP=210`。这些是墙钟保护上限，不是固定等待；控制器只在 Nav2 action
可发现且每台 `bt_navigator` 为 `active` 后启动。

## 根因和修复

1. 原控制器用融合图评分，却用私有图取前沿和最短路径；Nav2 也只消费私有图。跨机器人
   地图资源没有形成导航闭环。最终控制器、分段路径和 Nav2 全局静态层统一使用
   `/merge_map`。
2. Navfn 在动态扩展融合代价图上出现 `failed to create plan`。替换为已安装的
   `SmacPlanner2D`，并保留未知区规划。
3. 全局代价图原为 20 m 滚动窗口，而协调器允许 12 m 路径，长目标可能落到窗口外。
   全局层改为非滚动并跟随完整融合静态图；局部层仍滚动并使用各自 lidar。
4. 9–12 m 跨区目标经常在 Nav2 中不启动或恢复过久。中央 Dijkstra 路径超过 5 m 时，
   发送路径上的中间航点，到达后用最新融合图继续分配；任务终点和覆盖规则未改变。
5. 前沿分组、膨胀、信息增益和 Dijkstra 原有多层 Python 扫描，单机器人一次候选计算约
   1.165 秒。使用 SciPy 连通域、距离变换、二值膨胀和稀疏图 Dijkstra 后约 0.103 秒，
   约 11 倍加速，分配 timer 从 2 秒改为 1 秒。
6. 三机器人目标可能穿过队友当前位置。候选目标增加队友位置 1.2 m 排除区；最终三 seed
   碰撞为 0。
7. 旧 gate 只检查 action server 名称，lifecycle 激活失败时仍会放行并导致目标全部拒绝。
   新 gate 在 action 可发现后查询每台 `bt_navigator=active`，2 秒无响应即重试。

| 版本 | 结果 | 结论 |

| 快速局部效用 v1 | seed101 180 s 仅 88.95%，3 次碰撞 | 早期快但远目标和碰撞使尾段退化 |
| 10 s 无进展止损 v3 | seed101 131.0 s，零碰撞 | 有效但仍被跨图长目标限制 |
| 仅共享地图 + Navfn v4 | 137.4 s，规划失败仍存在 | 共享地图不能修复 Navfn 问题 |
| 仅 Smac + 私有地图 v5 | 180 s 仅 86.10% | 规划器正常但地图资源未共享 |
| 共享地图 + Smac v6 | seed101 83.7 s；三 seed 均值 124.1 s | 方向正确，滚动全局图和长目标仍有尾段 |
| 非滚动全局图 v7 | seed202 98.9 s、seed303 138.3 s | 消除大部分反复取消，但 seed 波动仍大 |
| 保留远目标直到接近 v8 | seed101 180 s 仅 84.91% | 远目标不分段会反复无进展 |
| 私有图分段 v9 | seed101 78.7 s、seed202 122.8 s | 中间点与 Nav2 的融合图可能不一致 |
| 全融合闭环 v10 | 两机器人三 seed 均值 111.3 s | 解决地图不一致；三机器人发现路径交叉碰撞 |
| 足迹 critic v11 | seed202 三机器人 129.0 s、9 次碰撞 | tb1 lifecycle 未 active，整轮拒绝目标，结果无效 |

所有失败、超时和无效运行均保留在 `log.md`，没有用失败样本之外的规则改动包装结果。

## 已知边界

- 结论只覆盖当前 world、共同起始区和固定 seeds 101/202/303；进入新场景前需扩 seed 和
  world 泛化实验。
- 95% 覆盖仍未作为 P1C 必选验收线。
- 当前 `/merge_map` 是理想即时通信上界。P2/P3 之后引入显式消息和网络因果闭环时，
  控制器与 Nav2 的地图输入必须经 gateway 交付，不能保留 ROS 旁路。
