# 2026-09-17 P2C 电池、返航和充电

## 结论

P2C 已实现并达到工程计划的退出条件，现等待用户验收。每台机器人运行独立的本地电池管理器；
低能量时按“预计返航能量 + 安全余量”抢占普通任务，返回互不重叠的专属充电位。充电期间不
重启 SLAM、不清空地图、不重置全局任务状态；充满后恢复原任务阶段。

保留的两机器人强制充电 episode 中，tb1/tb2 各完成一次返航和充电，最低能量分别为
6.81/6.66，没有耗尽；随后继续探索、发现目标并集合，在 190.1 仿真秒进入 `COMPLETE`。
全程零碰撞、零搜索重叠。

## 实现边界

- 新增每机器人一个 `battery_manager`，只读取本机 odom/TF 并直接调用本机 Nav2；总部只能
  根据 `ACTIVE/RETURNING/CHARGING/FAILED` 暂停或恢复任务，不能覆盖安全返航。
- 能量模型为 `E_next = E - c_move * distance - c_idle * elapsed`。P3 尚无应用字节账本，
  因此 `c_tx=0`，没有虚构通信能耗。
- 返航估计使用当前位置到充电位的直线距离、1.5 保守路径系数、0.18 m/s 标称速度和显式
  安全余量，同时计入移动与经过时间成本。
- 仿真充电位复用已知出生点：tb1 `(0,-0.45)`、tb2 `(0,0.45)`、tb3 `(0.45,0)`；充电半径
  0.25 m，任意两个充电区域不重叠。tb4 的出生位也独立。
- 机器人必须处于充电半径内且线/角速度不超过 0.05 m/s、0.10 rad/s，连续稳定达到配置的
  充电时间后才恢复满电。
- `/tbN/battery_state` 发布容量、初始/当前/最低能量、模式、返航/充电次数、充电时间和位置；
  失败经 `/battery_failure` 汇入权威 `/task_failure`。
- 明确失败原因为 `battery_exhausted:tbN`、`battery_return_unreachable:tbN` 和
  `battery_charge_timeout:tbN`；启用电池后缺失或超过 20 仿真秒未更新的本地状态另记为
  `battery_state_unavailable`。探索期现在也允许进入终态 `FAILED`。
- evaluator schema v6 写入逐机器人和 episode 汇总的电池/充电指标；smoke 的
  `--require-charge` 防止用“电池永远够用”空洞通过验收。

本检查点没有实现 P2D 场景矩阵、消息 gateway、通信字节能耗、充电排队或真实机械对接。

## 验证配置和命令

代码基于 `8868da6` 开始实现。环境为 ROS 2 Humble、仓库内 symlink install、Gazebo Classic、
`TURTLEBOT3_MODEL=waffle`；每次重试使用新的 `ROS_DOMAIN_ID`。保留成功轮的命令为：

```bash
python3 scripts/ros_smoke_test.py \
  --world my_world.world --robot-count 2 --gazebo-seed 303 \
  --startup-timeout 300 --message-timeout 90 --shutdown-timeout 60 \
  --evaluation-duration 300 --coverage-threshold 0 \
  --evaluation-wait-timeout 600 --target-detection --rally \
  --battery --require-charge --battery-initial-energy 18 \
  --battery-capacity 100 --battery-move-cost 1 \
  --battery-idle-cost 0.02 --battery-safety-margin 5 \
  --battery-charge-duration 10 --battery-return-timeout 120 \
  --battery-charge-timeout 60 \
  --target-x -4 --target-y 4 --target-max-distance 3 \
  --target-field-of-view 90 --target-confirmation-frames 3 \
  --episode-id p2c_forced_charge_2r_seed303_pilot3
```

无耗尽，按预期 timeout 结束，外层 smoke PASS。该轮只验证最终状态门，不替代上述完整任务。

## 保留的失败

- `pilot1`：两个 battery manager 在控制开始后因误用 `rclpy.Node` 的只读
  `subscriptions` 属性而退出；该轮人工中断，没有作为任务证据。内部容器改名后修复。
- `pilot2`：节点在约 2000 仿真秒后才启动，首个本地时钟跳变被错误计为此前全部空闲耗能，
  两台立即报告耗尽；同时暴露旧状态表不允许 `EXPLORE -> FAILED`。能量积分改用 odom 消息
  自带仿真时间戳，忽略单次超过 1 m 的非物理 odom 跳变，并允许探索期电池失败。
- `pilot3`：上述根因修复后通过；没有通过调大电量或移除强制充电来绕开失败。
