# P3A 显式消息协议与零损 gateway

日期：2026-09-22。P2D 已验收后，本报告记录 P3A 的实现、验证、正式矩阵和保留失败样本。

## 目标与实现

P3A 将 ideal/unlimited 通信也放入与后续网络替身相同的边界：机器人本地状态和检测候选由
`ideal_gateway` 包装为 `multi_robot_interfaces/GatewayEnvelope`，中央只消费
`/gateway/received/...`；中央导航命令由 `navigation_gateway` 转为机器人本地 Nav2 action。
消息含 `message_type`、`sender`、`recipient`、`sequence`、`correlation_id`、生成时间、任务阶段、
载荷长度、编码、TTL、ACK 序号和载荷。gateway 对每条上/下行路由维护序号、过期/旧序列检查、
接收存储、ACK 和事件记录；P3A 固定为零丢包、零附加时延。地图使用 zlib 压缩，但本阶段不把
压缩成本折算成 Wi-Fi 时间或能耗。

中央执行链不再直接订阅机器人 `/tbN/map`、`/tbN/odom`、`/tbN/tf` 或原始检测，不直接创建
机器人 Nav2 action client；机器人 Nav2 全局代价图使用 `/tbN/gateway/merge_map`。机器可检查
清单为 `src/multi_robot_exploration/config/p3a_forbidden_bypasses.json`，源码和运行时由
`bypass_audit` 同时检查。

## 验证

- `colcon build --symlink-install --packages-select multi_robot_interfaces multi_robot_exploration merge_map multi_robot --cmake-args -DPython3_EXECUTABLE=/usr/bin/python3 -DPYTHON_EXECUTABLE=/usr/bin/python3`：通过。
- `colcon test --packages-select multi_robot_exploration merge_map`：66 tests，0 errors，0 failures，2 skipped。
- `ros2 run multi_robot_exploration bypass_audit --robot-count 3 --wait-sec 10`：源码和 ROS graph 审计通过；正式 smoke 每轮也通过。

## 保留失败与限制

- ns3gym conda 环境缺少 ROS 构建所需的 `em`，且其 Python 缺少 pytest；因此构建/测试使用
  `/usr/bin/python3`，并保留该环境失败事实，不修改环境依赖。
- 早期 P3A pilot 在未限频的 gateway 下出现高 CPU 和任务超时；增加按消息类型限频及 zlib
  压缩后通过。早期 formal v1 的 lab seed 101 在旧输入门控下任务超时并记录碰撞；随后增加
  全体机器人输入就绪和全体电池 ACTIVE 门控，v2 正式矩阵不再复用该失败样本。
- pilot3 暴露单机器人返航时中央仍向其他机器人派发 rally 目标，产生 19 次碰撞；全体电池
  ACTIVE 全局暂停修复了该因果竞态。pilot4 的 2 秒运行时审计等待造成 `/headquarters_control`
  偶发假阴性，等待时间改为 10 秒；该启动前基础设施失败保留在实验日志中。
- P3A 仍是同机 zero-loss ideal gateway，不包含固定 delay/loss、Wi-Fi 干扰、ns-3 时间同步或
  重传代价；这些属于 P3B/P4。评估器可读 Gazebo 真值，但不向控制链发布；真实相机检测和
  压缩/传输成本校准留到后续阶段。
